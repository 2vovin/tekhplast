# PackingSolver как дополнительный серверный движок

2026-11-07. Рабочая интеграция: внешний процесс Python с нативным C++ ядром PackingSolver **0.1.1301**. Лицензия MIT. Wheel для Python 3.12+, x86_64, manylinux 2.27/2.28; URL и SHA256 закреплены в `server/packing/pin.json`. SHA256 проверен по метаданным PyPI и скачанному wheel. Поддерживается Ubuntu 24.04; готовый архив GitHub `latest` требует GLIBC_2.43, поэтому для сервера не используется. Старый benchmark с другим архивом не изменён; его контрольная сумма не ослаблялась.

## Конвейер

Сначала сервер воспроизводит полную схему опыта либо получает проверенный резервный результат ListPro. Если число листов выше нижней границы по площади и движок установлен, пробует направления H/V и 2, 3, неограниченное число стадий, до 5 секунд на вызов. Перестановки/повороты самого PackingSolver не являются доказательством PSS: сертификат преобразуется в группировку реальных деталей, пустые области уплотняются, строится **новая** последовательность CUT/ROTATE/END_RIP, затем выполняется независимый replay.

Перенос не сохраняет исходные координаты сертификата и не претендует на точное воспроизведение его операций. Новый план сохраняет исходные размеры, количество, пропил, обрезку и ограничения текстуры. Дробные размеры масштабируются целыми без округления, до трёх десятичных знаков; неподдерживаемая точность явно отклоняется.

Правила настоящей детали-якоря, неподвижного удерживаемого остатка, одного поворота физической заготовки сохранены. Некоторые трёхстадийные/неограниченные сертификаты отклоняются из-за составных первичных полос или неподдержанной структуры вложенности. Это консервативный адаптер; он не гарантирует преобразование всякого допустимого внешнего сертификата. Совместимость с конкретным станком не подтверждена.

Сервер сравнивает планы по действующей цели (листы, остатки/резы, повороты) и сохраняет только улучшение. Ошибка, отсутствие, несовместимость, тайм-аут или отклонение движка оставляют резервную карту доступной. При достижении нижней границы по листам сервер возвращает результат; минимальность резов, поворотов и остатков не доказана. Причины принятия/отклонения доступны в `result.search.nativeTrials`. Улучшения попадают в тот же проверяемый банк опыта.

## Фактический benchmark

Полные входы, времена каждого вызова и причины отказов: [report.json](report.json). Синтетические заказы: seed=7301, часть деталей с запретом поворота. ListPro сравнения: **короткий поиск, iterations=1**, не прежние длительные исследовательские результаты. Внешняя серия: по 3 секунды на каждую из 6 комбинаций H/V × 2/3/unlimited. Лучший допущенный внешний вариант в таблице выбирается по листам и числу резов. Сервер может остановиться раньше на первом результате, достигшем нижней границы.

| Заказ | Короткий ListPro, листов | PackingSolver после replay, листов | Резы ListPro / внешний | Повороты ListPro / внешний | Допущено попыток из 6 |
|---|---:|---:|---:|---:|---:|
| Исправленные 26 | 2 | 2 | 54 / 55 | 14 / 15 | 2 |
| Пользовательские 229 | 16 | 16 | 519 / 568 | 173 / 190 | 2 |
| Случайные 50 | 3 | 2 | 126 / 123 | 51 / 53 | 3 |
| Случайные 200 | 10 | 9 | 520 / 499 | 199 / 204 | 2 |

Максимальные цельные остатки (мм²) ListPro / внешние: 26 — 4116840 / 3732220; 229 — 2199150 / 407250; 50 — 4720170 / 490510; 200 — 3864350 / 1165710. Уменьшение числа листов важнее площади одного остатка. При равном числе листов худший внешний вариант не заменяет текущую карту.

Это сравнение различных бюджетов и методов, не доказательство превосходства PackingSolver при равном времени. Предыдущие однолистовые карты 26 деталей и пользовательская проверенная карта 229 деталей на 15 листах сохраняются. PackingSolver в этом испытании их не улучшил; 15 листов с нуля не найдено.

Полный server worker с установленным движком, холодная база, заказ random-50: 2 листа, 126 резов, 51 поворот, около 4,5 с локально; выбран первый H/2-кандидат. Это отдельный запуск с лимитом 5 секунд, поэтому отличается от лучшего варианта серии benchmark. Результат прошёл replay и сохранён в опыт. Время VPS не измерялось.

## Проверка и воспроизведение

`npm test`: **10095/10095**, ошибок нет. Включены реальные сертификаты, повреждённые строки/идентификаторы/количество/размеры, запрет поворота текстуры, дробные размеры, отсутствие процесса и отказ установленного внешнего движка с сохранением полного серверного результата. Проверено включение адаптера, runner, pin и установщика в runtime release. Chromium: 229 деталей, 15 карт из проверенной базы, без ошибок JavaScript.

```sh
LISTPRO_PACKING_PYTHON=/path/to/venv/bin/python node scripts/packing-pss-benchmark.js
node --test tests/packing-pss.test.js
npm test
```

CSV исходных сертификатов, JSON новых проверенных планов (с нумерованными операциями) и SVG каждого листа сохранены рядом. Бинарные файлы движка, пользовательский PDF и виртуальное окружение в GitHub не включены.

На VPS нужно установить обновление ListPro и выполнить `bash /opt/listpro/current/server/scripts/install-packing.sh`. Скрипт создаёт изолированное окружение `/opt/listpro/packing`, проверяет SHA256 wheel до установки и при необходимости устанавливает системный пакет python3-venv. Рабочие задачи не обращаются к внешним сервисам. HTTPS и существующие сайты скрипт не меняет. В этой среде VPS не подключён; фактическая установка на нём не выполнялась.
