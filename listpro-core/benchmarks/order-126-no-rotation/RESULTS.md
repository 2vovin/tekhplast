## Условный вариант: пять новых листов плюс имеющийся остаток

Отдельно независимо проверено размещение этих четырёх полос в
**готовом прямоугольном остатке 1364×415 мм** с уже подготовленными краями:

100 + 5 + 100 + 5 + 100 + 5 + 100 = 415 мм.

Требуются три параллельных сквозных реза длиной 1364 мм, без поворотов.
Для этой отдельной заготовки обрезка = 0 именно потому, что её края
уже должны быть подготовлены. Размеры основного листа и обрезка основного
заказа не менялись. Файлы offcut-prepared-input.json и offcut-prepared-result.json
содержат отдельный replay: 4 детали, 3 реза, 0 поворотов.

Если для остатка также необходима обрезка 10 мм с каждой стороны,
требуется исходная заготовка **1384×435 мм**. Этот сценарий также отдельно
проверен в offcut-raw-input.json и offcut-raw-result.json с trim=10.
Его размеры не выдаются за свойства готового остатка.

Таким образом, при наличии подходящего пригодного остатка можно использовать
пять новых листов и этот остаток вместо шестого целого листа.
Наличие такого остатка пользователь не подтверждал: результат основного
заказа остаётся шестилистовым, а условный вариант не импортировался как полный
пятилистовой заказ в базу опыта. Совокупный учёт первых пяти карт и четырёх
полос на отдельном остатке проверен регрессионным тестом для всех 126 деталей.

## Независимая технологическая проверка

- Геометрия: корректна.
- Абстрактное гильотинное дерево: корректно.
- PSS completed-rip-v1: корректно.
- Конкретный реальный станок: совместимость не подтверждена.

Исходные листы и удерживаемые остатки не поворачиваются.
Серия параллельных резов завершается до обработки отделённых полос.
Допустим максимум один физический поворот каждой отделённой заготовки.
Ориентация готовых деталей остаётся ровно длина × ширина исходного заказа.
Во всех 126 прямоугольниках ширина равна заданной длине, высота — заданной ширине.
В выбранном плане нет торцовок с выходом диска за край (edgeFinishingCuts=0),
хотя абстрактный профиль в принципе разрешает такую операцию.
Размеры зажима, подачи и минимальных заготовок реального станка неизвестны;
это не управляющая программа ЧПУ.

## Поиск и сравнение

Основной результат получен штатным completed-rip-search:
iterations=100, seed=18569, параметры неизменны.
Он выбран вместо более дорогого найденного нативного варианта:

| Вариант | Листов | Резов | Поворотов заготовок | Крупнейший остаток, м² |
|---|---:|---:|---:|---:|
| Выбранный штатный JS | 6 | 228 | 30 | 3,794700 |
| PackingSolver + независимый PSS replay | 6 | 260 | 46 | 1.929460 |

Нативный генератор 0.1.1301 проверен на обеих первых осях, с объединением
одинаковых реальных типов и без него, с 2, 3 и неограниченным числом стадий.
20 вызовов: двенадцать двухстадийных предложений приняты,
восемь более глубоких отклонены replay/конвертером из-за отсутствия настоящего
якоря, запрещённого поворота или непараллельных полос.
Геометрические предложения не принимались за технологическое доказательство.

Дополнительные исследовательские приоритеты узких групп также не дали 5 листов.
Эти временные предпочтения не внедрялись в исходники штатного алгоритма.
Выбранный результат сохраняет остаток на всю полезную длину листа и имеет
меньше резов и поворотов. Глобальная оптимальность трудоёмкости не доказана.

## Файлы и воспроизведение

input.tsv и input.json содержат точные исходные строки.
result.json — полный шестилистовой план; patterns.json — его шаблоны.
maps.pdf — 6 страниц с перечнями деталей справа.
maps.html, sheet-N.svg, primary-N.svg, strip-N-M.svg — общие и отдельные карты.
operations.csv, sequence.html — все 558 шагов, включая реальные физические
заготовки перед резом, размеры, оси, координаты и повороты.
verification.json — независимый replay и инвентаризация.
alternatives/native-result.json и alternatives/native-certificate.csv —
нативная альтернатива. Она не является источником выбранной JS-карты.
search-native.json и ci-search.json содержат измерения и причины отклонения.
Все предыдущие заказы сохранены отдельно.

Из listpro-core/:

```sh
node benchmarks/order-126-no-rotation/verify.cjs
node --test tests/order-126-no-rotation.test.js
node benchmarks/order-126-no-rotation/run-js.cjs
node benchmarks/order-126-no-rotation/export.cjs
node benchmarks/order-126-no-rotation/render-pdf.cjs
npm test
npm run benchmark
```

Нативное сравнение запускается отдельно:

```sh
node benchmarks/order-126-no-rotation/run-native.cjs
```

Оно сохраняет свои результаты под именами native-result/certificate/search,
не заменяя выбранную JS-карту худшей. Временное venv создаётся только при
отсутствии LISTPRO_PACKING_PYTHON; точный wheel проходит проверку SHA256
из server/packing/pin.json. Требуются Python >=3.12 и x86_64 Linux.
Основная проверка JSON, экспорт и JS-поиск не требуют Python или сети.
