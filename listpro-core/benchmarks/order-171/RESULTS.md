# Раскрой заказа: 98 строк / 171 деталь

**Найдено: 11 листов 2750×1830 мм, 349 физических резов, 99 поворотов отделённых заготовок.** Исходный лист и удерживаемые остатки не поворачиваются. Все 171 экземпляр проверены независимым replay.

## Входные данные

Источник — таблица пользователя из 98 строк. Первая строка 2108×968×1 является деталью, а не заголовком. Две такие строки сохранены отдельно. Номер позиции соответствует порядку строки в сообщении; повторяющиеся размеры не объединены и не потеряны.

Пользователь подтвердил лист **2750×1830 мм**, пропил **5 мм**, обрезку **10 мм с каждой стороны**, затем явно разрешил: **«Можно крутить все детали»**. Поэтому для всех строк задано `grain=false`; исходные длина/ширина не переставлялись во входной спецификации, поворот каждого размещённого экземпляра записан отдельно.

Полумиллиметровые размеры 573,5; 278,5; 273,5; 118,5 сохранены без округления. JSON использует десятичную точку. Площадь заказа **46 160 513 мм²**.

Выбран первоначальный распуск V в координатах материала; профиль `order-171-held-V-v1` допускает одну машинную ось V. Это выбранная первоначальная установка листа, **не** свободное чередование двух осей и не поворот исходного листа в середине работы. Отделённые полосы затем обрабатываются как новые заготовки. В каждой серии удерживаемый HIGH-остаток продолжает тот же распуск без снятия; все рабочие полосы текущей серии отделяются до дальнейшей обработки.

Проверка отличает индивидуальный поворот blankId, повороты по цепочке и разрешённый поворот готовой детали. **60 деталей** размещены с перестановкой длины и ширины. Физических поворотов отделённых заготовок — **99**; максимум по цепочке — **4**; уровней смены материальной оси — **5**. Повторных поворотов одного blankId, поворотов удерживаемых остатков и пересечений деталей пропилом нет в проверенном плане.

## Воспроизводимость

Новый модуль `src/adaptive-held-strip.js` выбирает реальные размеры первичных полос отдельно для каждого листа. Он использует рекурсивное заполнение, линейное DP, перестановки, физически проверенные улучшения и перестройку групп листов. Внутренний фильтр не позволяет удерживаемому хвосту менять направление; независимый `held-strip-validator.js` не изменён и повторно проверяет весь результат.

Бюджет: seed=42; 100 вариантов H, 100 вариантов V; три окрестности по 100 вариантов. В V перестроены группы (номера с нуля) [5,7,9,10], [5,7,8,9,10], [6,7,9,10]. Лучший результат получен для второй группы: пять листов / 87 деталей перестроены с сохранением всего исходного заказа. Каждая проверяемая комбинация сохраняет соответствие исходных rowId / instanceId.

```sh
npm test
npm run benchmark:order-171
npm run benchmark:order-171 -- --write
npm run benchmark
```

Последняя команда сохраняет весь исторический benchmark и добавляет новый заказ. Опция `--write` у отдельного benchmark воспроизводит и записывает карты, JSON, CSV и HTML. Тесты проверяют все количества и дробные размеры, разрешённые повороты, оба направления первого распуска, восстановление идентификаторов после перестройки, неизменность входа, покрытие всех операций визуализацией и независимые ограничения оборудования.

Предварительный V8 поиск: H — 37 560 мс, V — 38 335 мс; три перестройки — 5024 / 12 760 / 2610 мс. Фактические измерения Node и результаты GitHub Actions будут сохранены в `ci.json`; времена разных сред не следует напрямую сравнивать.

Нулевые минимальные размеры в исследовательском профиле означают отсутствие заданного ограничения, а не доказательство удержания. Карты не являются управляющей программой ЧПУ.
