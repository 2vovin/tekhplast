# Заказ 234 детали: раскрой на 14 целых листах

Дата: 27.11.2026. Исходные данные: **75 строк / 234 экземпляра**.
Пользователь отдельно подтвердил: **повороты всех деталей разрешены**.
Размеры с половиной миллиметра сохранены точно, включая
819×779,5, 1003×537,5 и 779,5×168 мм. Повторяющиеся строки имеют собственные номера.

**Все 234 детали размещены на 14 целых листах текущего заказа.**
Наличие отдельного складского остатка не требуется.
Геометрия, гильотинное дерево и последовательность PSS проверены независимо.

## Доказательство минимального числа листов

Площадь 13 полезных полей: 13×2730×1810 = **64 236 900 мм²**.
Детали занимают **65 644 689 мм²**, что больше на 1 407 789 мм².
Даже площадь 13 целых листов без обрезки и пропилов, 65 422 500 мм²,
меньше площади деталей. Следовательно, меньше 14 листов недостаточно.

Независимый replay подтверждает существование раскроя на 14 листах,
поэтому **минимально именно число листов** при заданных параметрах.
Оптимальность количества резов, поворотов, трудоёмкости и формы остатков не доказана.

## Как использован предыдущий расчёт

За основу взята проверенная схема прежнего заказа из 221 детали на 13 листах:
[исходный сохранённый план](https://github.com/2vovin/tekhplast/blob/27437e17210f1ed553d461f33d156ca4f4d2a104/listpro-core/benchmarks/order-221-target13/result.json).

Новая утилита run-reuse.cjs:

1. Проверяет старый план независимым валидатором и совпадение параметров материала.
2. Автоматически сопоставляет реальные размеры старых деталей с новыми строками,
   сохраняя размеры, разрешённую ориентацию и количества.
3. Перебирает группы новых реальных деталей и разрешённые ориентации, которые
   можно добавить самостоятельными первичными полосами в оставшийся распуск.
4. Принимает расширение только после полного replay и проверки сохранения
   координат всех ранее размещённых деталей.
5. Рассчитывает остаток заказа штатным многовариантным JS-поиском
   и заново строит и проверяет полный план всех 234 деталей.

В этом заказе на 13-м листе после прежних четырёх полос оставалось
747 мм полезной ширины. В текущем первичном распуске из него последовательно
отделяются **две настоящие полосы по 297 мм** для двух дополнительных
деталей 1800×297. Каждая полоса имеет собственную реальную деталь-якорь.
После двух отделений с пропилами остаётся 747−297−5−297−5 = **143 мм**.
Общая составная «деталь» из двух полос не создавалась; удерживаемый остаток
не поворачивался. Эти два новых экземпляра — строка №75, экземпляры 3 и 4.

Таким образом, на первых 13 листах размещены 223 детали, а оставшиеся
11 — на отдельном 14-м листе. Расчёт хвоста использует seed=1127,
по 50 попыток для вариантов оси и набора кандидатов, плюс консервативные
начальные варианты. search.json хранит фактическую статистику и время прогона.

Это повторное использование вычисленной схемы: все 14 листов принадлежат
текущему полному заказу. Размеры деталей и ширина пропила не менялись.

Утилита принимает другой старый input/result через аргументы CLI.
В функции reuseAndExtend нет фиксированных размеров 1800/297 или номера №75:
возможные расширения выбираются из реального остатка нового заказа.
Предыдущие исходники алгоритмов и эталон на 221 деталь не изменены.

## Технологические границы

Статусы: geometryValid=true, abstractCutTreeValid=true,
targetPSSModelValid=true, realMachineFeasibility=unknown.

Использован существующий абстрактный профиль completed-rip-v1:
удерживаемая сторона HIGH_MATERIAL, завершение серии параллельных резов
перед обработкой отделённых полос, maxTurnsPerBlank=1,
maxSheetTurns=0. Каждый CUT и поворот имеет номер, входной blankId,
выходные blankId, текущие размеры, ориентацию, ось и координаты.
Новые blankId удерживаемой части не дают права её поворачивать.
Геометрическая раскладка сама по себе доказательством PSS не считалась.

Существующий профиль разрешает торцовку с выходом диска за край;
в плане 40 таких операций. Это унаследованное условие профиля,
не новое послабление ради 14 листов. Реальные возможности зажима,
подачи, хода пилы, минимальных заготовок и такой торцовки неизвестны.
Не создана управляющая программа ЧПУ и не заявлена сертификация для станка.
Максимальные четыре поворота по цепочке получились в этом плане;
они не объявляются паспортным пределом оборудования.

## Файлы

- input.tsv и input.json — исходный заказ, запятые в TSV сохранены.
- result.json — весь план на 14 листах, геометрия, операции, профиль и replay.
- patterns.json — повторяемые полосные шаблоны.
- verification.json — независимые статусы, размеры и инвентаризация всех строк.
- maps.pdf — **14 векторных страниц**, карта и список деталей рядом.
- maps.html — просмотр 1/2/3 листа в ряд, печать со списком деталей справа.
- sheet-N.svg — отдельные карты листов.
- primary-N.svg и primary-strips.json — первичные полосы.
- strip-N-M.svg — отдельные карты всех 61 первичных полос.
- operations.csv — все 1471 шага.
- sequence.html — текущая физическая заготовка перед каждой операцией,
  реальная линия CUT, размеры, ориентация и дочерние части.
- run-reuse.cjs — рабочая утилита повторного расчёта из проверенного подзаказа.
- search.json — фактическая статистика поиска.
- artifact-checks.json — контроль количества страниц, карт и геометрических экземпляров.

На картах показан номер строки без суффикса экземпляра.
Размеры подписаны по соответствующим сторонам; маленькие детали имеют
номер и размеры в соседнем перечне. Номер детали и номер реза различаются.

## Воспроизведение

Из папки listpro-core/:

```sh
node benchmarks/order-234-target14/verify.cjs
node --test tests/order-234-target14.test.js
node benchmarks/order-234-target14/run-reuse.cjs
node benchmarks/order-234-target14/export.cjs
node benchmarks/order-234-target14/render-pdf.cjs
npm test
npm run benchmark
```

Для другой ранее сохранённой схемы:

```sh
node benchmarks/order-234-target14/run-reuse.cjs /path/to/prior-input.json /path/to/prior-result.json
```

Node >=20. Сторонние пакеты, Python и сеть для этого расчёта не требуются.
Код повторного расчёта заново генерирует технологический план; не копирует
прежний список операций как доказательство нового заказа.
При отсутствии совместимого старого подзаказа утилита сообщает ошибку,
не подставляет другую геометрию или количество.

## Проверки и GitHub Actions

Четыре новые регрессии проверяют:
точные 75 строк/234 детали/14 листов и дробные размеры;
повторный полный расчёт из старой схемы;
отклонение округления каждой исходной половины миллиметра;
отклонение второго поворота той же физической заготовки.
Они выполнены во вспомогательной JS-среде и включены в npm test.
PDF проверен на 14 страниц, перекрёстные ссылки объектов, а SVG — на 234 экземпляра.

После сохранения ветки полный набор тестов и benchmark выполняются
[существующим GitHub Actions workflow](https://github.com/2vovin/tekhplast/actions/workflows/listpro-core.yml?query=branch%3Alistpro-core).
У исторического внешнего сравнения Brain 2.0 ранее была известная ошибка:
`PackingSolver release changed: pinned SHA256 mismatch; never execute an unpinned binary`.
Этот новый расчёт не запускает внешний PackingSolver; старое сравнение и
его проверка хеша не изменялись. Ошибка исторического benchmark, если
повторится, не означает ошибку новой карты, но общий workflow тогда не зелёный.

Все изменения находятся в listpro-core/. main и сайт «Техпласт» не изменены.
