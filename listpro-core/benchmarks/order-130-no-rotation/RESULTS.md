# Заказ без поворота деталей: 12 строк, 130 экземпляров

Исходные параметры: лист 2750×1830 мм, обрезка 10 мм с каждой стороны,
полезное поле 2730×1810 мм, пропил 5 мм.
**Все детали сохраняют заданную ориентацию длина × ширина.**
Повторяющиеся строки учтены отдельно с исходными номерами.

Площадь деталей: **23,084562 м²**.
Минимум по одной лишь площади — 5 листов: на четырёх полезная площадь
19,765200 м², меньше площади деталей. Эта оценка сама по себе не доказывает,
что раскрой на пяти листах выполним.

Важная проверка размеров: две детали длиной 1364 мм рядом при пропиле 5 мм
занимают 2733 мм, что больше полезных 2730 мм. Размеры не округлялись,
отступы и ширина пропила не уменьшались.

## Проверка и технология

Независимый replay: геометрия корректна, гильотинное дерево корректно,
полосная последовательность completed-rip-v1 корректна.
**Совместимость с конкретным реальным станком не подтверждена.**

В материальной системе координат ни одна деталь не повёрнута относительно заказа.
Это отдельно от физических переустановок отделённых полос:
исходные листы и удерживаемые остатки не поворачиваются, текущая серия
параллельных резов завершается до обработки отделённых заготовок.
У каждой физической заготовки допускается не более одного поворота.
Профиль, роли, размеры, координаты и счётчики воспроизведены
src/completed-rip-validator.js; номер строки/экземпляра, количество и размеры проверены.
Никаких фиктивных составных деталей-якорей не добавлялось.

Существующий абстрактный профиль допускает выход диска за край при торцовке.
Подача, зажим, длина хода, минимальные размеры и такая торцовка для реального
оборудования неизвестны. Этот результат не является управляющей программой ЧПУ.

## Поиск

Штатный JS-поиск и нативный PackingSolver 0.1.1301 рассматривались как генераторы.
Предложение CSV преобразуется в полосные шаблоны, затем строится **новый**
физический план, и только независимая проверка допускает его к сохранению.
Нативная геометрическая раскладка не использовалась как доказательство пригодности.

Перебирались обе первичные оси H/V и отдельное объединение одинаковых реальных
типов с последующим восстановлением исходных строк и количеств.
Для двухстадийного генератора задавались пределы времени 5, 15, 30 с:
это максимальные бюджеты, фактические вызовы могли завершиться раньше.
Дополнительно исследованы предложения с тремя стадиями и без ограничения
числа стадий. Требования replay и размеры заказа при этом не ослаблялись.
Все принятые варианты/причины отклонений и фактическое время сохранены в search.json.
Лучший результат сохранён после независимой проверки.

## Файлы

- input.tsv, input.json — точный исходный список.
- result.json — размещения, дерево, профиль, все операции и проверка.
- patterns.json — полосные шаблоны найденного решения.
- certificate.csv — исходное предложение внешнего генератора выбранного варианта.
- verification.json — независимая проверка, количества и оценка по площади.
- maps.pdf — отдельная векторная страница на каждый лист, справа список деталей.
- maps.html — все листы 1/2/3 в ряд; печать по листам со списком деталей.
- sheet-N.svg, primary-N.svg, strip-N-M.svg — листы, первичные полосы, полосы.
- sequence.html — покадровая обработка текущей физической заготовки.
- operations.csv — пронумерованные резы, повороты, подачи и границы серий.
- search.json, ci-search.json — происхождение и фактические результаты поиска.

Карты подписаны номерами исходных строк без суффикса экземпляра.
Размеры показаны вдоль соответствующих сторон; на мелких деталях — только номер.

## Воспроизведение

Из listpro-core/:

```sh
node benchmarks/order-130-no-rotation/verify.cjs
node --test tests/order-130-no-rotation.test.js
node benchmarks/order-130-no-rotation/export.cjs
node benchmarks/order-130-no-rotation/render-pdf.cjs
npm test
npm run benchmark
```

Новый расчёт без использования сохранённых координат:

```sh
node benchmarks/order-130-no-rotation/run-native.cjs
```

Проверка JSON не требует сети или Python. Новый нативный поиск требует
Node >=20, Python >=3.12, x86_64 Linux. Если LISTPRO_PACKING_PYTHON не задан,
создаётся временное пользовательское venv, а колесо устанавливается только после
проверки точного SHA256 из server/packing/pin.json. Системный Python, серверный /opt,
сайт пользователя и main не меняются.

## GitHub Actions

При подготовке заказа общий набор из 10122 тестов прошёл.
Нативный поиск и независимый replay нового заказа выполнены на runner.
Общий исторический benchmark позднее останавливается на известной ошибке
`PackingSolver release changed: pinned SHA256 mismatch; never execute an unpinned binary`
в старом внешнем сравнении Brain 2.0. Эта ошибка не относится к проверенному
колесу 0.1.1301 или сохранённой карте. Защита хеша не отключалась, исторический pin
и предыдущие оптимизаторы не менялись. Общий workflow нельзя считать зелёным.
Добавлены отдельные регрессии нового заказа на точные размеры/количества и
недопустимый поворот детали. После сохранения CI воспроизводит их вместе
с остальными тестами, не устанавливая движок поиска заново.
