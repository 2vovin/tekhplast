# Ранняя выдача проверенной карты

2026-11-07. Пользователь попросил ускорить расчёт. В серверном worker уже создавались и сохранялись полные проверенные checkpoint, но API/браузер выдавали карту только после завершения всего поиска. Изменение сокращает ожидание первой карты и позволяет пользоваться ею, пока идёт дальнейшая оптимизация.

## Поведение

- API присваивает каждому улучшенному checkpoint ревизию. `GET /api/jobs/:id?after=N` возвращает полный `result`, если появилась более новая ревизия. Во время поиска сохраняются `status=running`, `searchComplete=false`.
- Если карта не изменилась, ответ содержит только краткий статус и прогресс. Большой JSON и SVG не передаются и не перерисовываются на каждом опросе.
- Браузер сразу показывает все листы полного заказа; просмотр, печать и экспорт доступны. Список деталей и размеры сохраняются. Новая карта появляется только после независимого replay и проверки исходного заказа существующим worker.
- «Оставить этот раскрой» останавливает поиск, сохраняя показанную карту. Уже записанный опыт остаётся в базе. Ошибка записи опыта по-прежнему отображается отдельно.
- Ответ опроса, пришедший после отмены/смены запроса, не может заменить карту. При улучшении сохраняется выбранный номер листа в пределах нового количества листов; при неизменившейся карте навигация не сбрасывается.
- Старый клиент без `after` сохраняет прежний протокол: полный результат после завершения. Настройки глубины поиска, сравнение качества карт и технологические ограничения не менялись.

## Измерения

Локальная машина исследования: Node.js 24.19.0, Linux x86_64, 5 доступных CPU. VPS пользователя не обновлялся и не измерялся. Все 100 строк / 127 экземпляров исходного заказа сохранены, повороты деталей разрешены, лист 2750×1830, обрезка 10, пропил 5.

|Проверка|Фактический результат|
|---|---|
|Первый полный checkpoint, пустая база|562 мс|
|Первая карта через API, опрос 100 мс|720 мс|
|Карта в Chromium, штатный опрос 700 мс|986 мс|
|Повторный API-расчёт из накопленного в этом испытании опыта|220 мс до карты|
|Момент завершения того же холодного API-задания|8187 мс|
|Неизменившийся ответ статуса, максимум в холодном испытании|241 байт|

В API-измерении задан **исследовательский мягкий бюджет 8 с и жёсткий 12 с**. 8187 мс — время выдачи результата старому клиенту для этого же короткого задания; оно не подменяет измерение реального 5-минутного сеанса. Рабочие бюджеты 240/300 с сохранены.

Первая холодная карта содержала 19 листов; за короткое испытание улучшилась до 18. Повторный запрос показал эти сохранённые 18 листов. Ранее проверенный исследовательский вариант на 17 листах в пустую базу этого испытания не импортировался. Таким образом, цифры времени относятся к раннему допустимому решению, а не к получению 17 листов с нуля или к доказанной оптимальности. Полный поиск и его качество требуют отдельного времени.

Браузер проверил: карту при активном поиске, все 127 деталей, доступность печати, навигацию при опросе, остановку без потери карты, экспорт полного JSON и независимый `completed-rip-v1` replay экспортированной карты. Ошибок JavaScript нет. Исходные измерения: `server/reports/live-preview/`. Повторная браузерная проверка после правки сохранения выбранной операции: 1062 мс до карты, все проверки пройдены.

Полный набор `npm test`: **10100 пройдено, 0 ошибок**. Отдельный серверный набор: 11/11. `npm run benchmark` пройден локально; архивное внешнее сравнение PackingSolver, включаемое только в CI/явным флагом, в этот запуск не входило.

## Воспроизведение

Из `listpro-core/`:

```sh
node --test server/tests/server.test.cjs
node server/scripts/benchmark-preview.cjs /tmp/preview-benchmark.json
CHROMIUM_PATH=/usr/bin/chromium node server/scripts/browser-live-preview-check.cjs /tmp/preview-browser.json
npm test
npm run benchmark
```

Chromium и Playwright нужны только для браузерной проверки, а не для рабочего сервера. Пользовательские примеры и результаты измерений не включаются в runtime release. Обновление рабочего сервера — стандартным `server/scripts/install.sh`; существующие настройки HTTPS-прокси и база опыта сохраняются. Это изменение доступно в исходниках и требует обновления установленной версии VPS.
