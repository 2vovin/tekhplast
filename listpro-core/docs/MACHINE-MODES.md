# ЛистПро — разные технологические режимы для разных станков

## Принцип (уточнение пользователя)

В программе **одно общее ядро геометрии и оптимизации**, но **разные технологические профили и валидаторы**. Не существует одного универсального запрета на поворот или общих для всех правил первичных полос.

### 1. Форматно-раскроечный станок — `FORMAT_SAW`

- Исходный лист можно физически поворачивать, как и отрезанные заготовки/полосы, если это допускает конкретное оборудование и безопасная организация работы.
- Нет обязательной стадии «сначала все первичные полосы, потом их обработка»; можно после отделения и обработки заготовки вернуться к другой заготовке, если она доступна. Возможны разные ориентации последующих операций.
- Можно использовать варианты раннего геометрического гильотинного раскроя **после независимой проверки физически осуществимой последовательности полных прямолинейных резов**. Простая карта прямоугольников без дерева операций сама по себе не доказывает исполнимость.
- **Не применять** к данному режиму критерий «деталь-якорь», запрет поворота `PRIMARY_REMAINDER`, принудительный полный первичный распуск и ограничение «один поворот на blankId» — эти требования относятся к отдельному профилю пильного центра, а не являются универсальными.
- Не задавать искусственный предел количества поворотов; если у конкретного станка/процесса есть предел, задавать его явно в профиле.
- Не допускать поворота **детали относительно текстуры исходного материала** там, где пользователь запретил поворот. Физически повернуть целую плиту не значит изменить направление рисунка внутри детали.

### 2. Пильный центр — `PANEL_SAW_STAGED`

- Строгая стадийная последовательность: **исходный лист → первичные полосы → подполосы → готовые детали**.
- Основной остаток исходного листа продолжает первичный распуск без разворота *после начала серии резов*; у каждой отделённой рабочей полосы свой учёт допустимых поворотов (для согласованного сценария не более 1 поворота на физический `blankId`).
- Переход основного остатка в рабочую полосу допустим только по явно доказанному технологическому правилу с **реальной деталью-якорем**, а не за счёт суммы нескольких мелких деталей, согласно `STAGED-PANEL-SAW.md`.
- Поворот исходной плиты **до** первой серии, если разрешён, задаётся отдельно; самовольная смена ориентации основного остатка после частичного распила запрещена.
- Каждый рез и поворот моделируется как действие над конкретной заготовкой с `blankId`, ролью, машинной ориентацией и историей. Независимый replay валидатор обязан проверять не только геометрию, но и технологическую допустимость.
- Без паспортных ограничений захватов, подачи, прижимов, длины резов и размеров заготовок результаты только условны для абстрактного профиля, а не подтверждены на БАЗИС или конкретном станке.

## Общие условия

- Размеры деталей, количество, текстура, ширина пропила, обрезка краёв должны соблюдаться.
- Приоритеты оптимизации по умолчанию: все детали и минимум листов; затем пригодные цельные прямоугольные остатки; затем технологическая простота (число резов, длина, операции, повороты).
- Режим выбирается **по типу оборудования**, а не по отдельным переключателям качества оптимизации. При смене станка одна и та же спецификация деталей может давать разные карты.
- Не показывать режим `FORMAT_SAW` как пригодный для `PANEL_SAW_STAGED` без повторной оптимизации и проверки.
- Независимые тесты: карта с `PRIMARY_REMAINDER` → `ROTATE_90` после первичного отделения должна быть **отклонена** в `PANEL_SAW_STAGED`, но может быть **допустима** для `FORMAT_SAW`, если дерево резов реально исполнимо и соблюдены прочие ограничения; соответствующее различие обязательно проверять.
- Отдельный валидатор и статус для каждого профиля. Отчёт должен обозначать для какого оборудования признана карта допустимой.

## Реализация для Codex

1. Существующий гильотинный геометрический валидатор — общий.
2. `FORMAT_SAW`: отдельный планировщик последовательности резов и физический валидатор гильотинных операций без обязательных первичных полос.
3. `PANEL_SAW_STAGED`: отдельный планировщик по полосам с ролями `PRIMARY_REMAINDER`/`DETACHED_PRIMARY_STRIP` и проверкой права их поворота.
4. Учитывать многостадийные деревья и определять перемещение/переворот куска в локальных машинных координатах, но не заявлять совместимость с реальным оборудованием без его профиля.
5. Создать парные контрольные тесты на одном наборе деталей и одинаковых требованиях к текстуре, показывающие отличие разрешённых операций. Отчёты сохранять в разных артефактах; не перезаписывать историю Brain 1.1.
