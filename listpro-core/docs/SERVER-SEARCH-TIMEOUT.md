# Сервер: повторный поиск, тайм-аут и сохранение опыта

2026-11-07. По сообщению пользователя выявлены два дефекта конвейера: до обращения к базе запускался свежий поиск, а запись опыта происходила только при завершении задачи. VPS в этой среде недоступен; фактическое содержимое его базы и состояние установки не проверялись.

## Изменения

- Полные точные схемы воспроизводятся до нового поиска; поиск по частичным совпадениям в этой фазе отключён. Все схемы заново компилируются и проходят независимый replay с текущими параметрами заказа.
- Если проверенная полная схема достигла нижней границы числа листов, она возвращается сразу. Более дешёвые резы, повороты и остатки при этом не объявляются оптимальными.
- Полные проверенные улучшения записываются перед отправкой checkpoint. Тайм-аут больше не исключает такие карты из обучения; частичные подзаказы по-прежнему не публикуются.
- Один запрос увеличивает счётчик расчётов один раз независимо от числа улучшений. Блокировка и атомарная замена файла сохраняются.
- Поиск проверяет мягкий бюджет 240 секунд между попытками; жёсткий лимит 300 секунд остаётся страховкой от одной долгой попытки.
- Ошибки записи не уничтожают карту и явно отражаются в `experienceInfo.saved=false`. Уведомление тайм-аута учитывает фактическое сохранение.

## Проверка

Заказ 229 деталей с отдельно загруженной пользовательской схемой на 15 листах: worker вернул проверенные 15 листов примерно за 0,3 секунды на локальной машине даже при бюджете нового поиска 1 мс. Проверено отсутствие нового перебора. Это повторное использование проверенной пользовательской схемы, не самостоятельное нахождение 15 листов с нуля и не гарантия времени VPS.

Принудительное прерывание холодного расчёта этого заказа через 15 секунд: возвращена полная карта 229 деталей, размеры и количество сохранены; карта прошла независимый replay, осталась в банке и воспроизводится из него без нового поиска. Число листов нового поиска не улучшалось в этой задаче.

Добавлены проверки частичной/несовпадающей схемы (быстрая фаза не вызывает поиск), остановки между кандидатами с сохранением результата, повторного использования полного заказа при минимальном бюджете, ошибки записи базы. Предыдущие геометрические и технологические регрессии сохранены.
