## Реализация

`src/pss-waste-local.js`:

- Перечисляет все положительные настоящие waste-листья дерева, сопоставляет их с живыми SECONDARY_BLANK из независимого replay. Области PRIMARY_REMAINDER учитываются в инвентаризации, но не разрешаются к локальному заполнению.
- Сохраняет путь дерева, координаты, полосу, физический ID, ориентацию, счётчик и причину пригодности/отклонения. Простые пустые области на рисунке не считаются заготовками.
- Локальный DP строит гильотинные паттерны из настоящих экземпляров, с направлением текстуры и всеми пропилами. Проверяет оба порядка подрезки. Предусмотрены бюджеты состояний, комбинаций, подмножеств и посещённых узлов.
- Разворачивает паттерн в новое CUT-поддерево и пересобирает списки деталей, остатков и номера резов.

`src/pss-recovery.js`:

- `recoverWaste(order,previous,{profile})` выполняет обязательную дозагрузку существующих отходов.
- `searchPSS14(order,{profile,previous})` дополнительно перестраивает вторичные поддеревья и группы хвостов нескольких полос. Без previous сначала строит базовый план через PSS 1.3, а перед возвратом многолистового результата обязательно выполняет recovery. «Открытие листа» здесь — решение планировщика, а не отправка команды станку.
- Пул доноров содержит реальные экземпляры со всех более поздних листов. Каждый перенос удаляет их из доноров, перепланирует оставшиеся экземпляры с сохранёнными ID и удаляет пустые листы.
- Ни один план не принимается до полного нового `makePSSPlan` и независимого `validatePSS`. Кэшированные valid-флаги, метрики и список заготовок игнорируются: исходный план заново воспроизводится.
- Оценка: число листов; затем площади деталей на поздних листах (начиная с последнего); затем крупнейший физический остаток, резы, повороты, длина, операции. Новый приоритет загрузки предыдущих листов не позволяет отвергнуть полезный перенос только из-за дополнительных резов. Это намеренно отличается от оценки 1.3 и отражено в сравнении.
- Первичные полосы принимающего листа и реальные ведущие якоря сохраняются; заменяются только допустимые вторичные поддеревья. Основной остаток не поворачивается и не переименовывается ради дозагрузки.

Независимые `pss-validator.js` и `physical-replay.js` оставлены без изменений. Они не импортируют новый оптимизатор.

## Ограничения

Поиск ограничен бюджетами и не гарантирует полного заполнения, оптимальности или возможности одного листа. Recovery не объединяет визуально соседние отходы через уже существующий пропил. Глубокая перестройка может заменить вторичное поддерево целиком, но не меняет ведущий якорь или правила PRIMARY_REMAINDER. В этой версии не исследуются новые первичные ширины/оси принимающего листа — это остаётся отдельным уровнем PSS 1.3; после него доступен recovery.

Сохранённый профиль абстрактный: машинная ось V, 0/1 поворот рабочей заготовки, исходный лист только до первого реза, реальные ведущие якоря. Минимальные размеры захвата и другие паспортные ограничения конкретного станка неизвестны. Узкие остатки, включая 3 мм, допустимы только по текущему абстрактному профилю; пригодность такой операции для реального оборудования не подтверждена. Управляющая программа ЧПУ и интеграция БАЗИС не создавались.

## Что изменилось в алгоритме

- `src/pss-improve.js`: самостоятельная стадия оптимизации PSS 1.3 с API `searchPSS13`. Проверяет исходное сохранённое решение, поддерживает несколько конфигураций, сравнивает только независимо проверенные планы. Порядок цели: листы, крупнейший **физический** полезный остаток, резы, повороты, длина, все операции.
- `src/pss-tail-allocation.js`: группировка по размерам и разрешению текстуры, перечисление ширин настоящих деталей-якорей и распределение счётчиков экземпляров между хвостами **нескольких** полос. Отдельно выбирается ось для каждого листа.
- `src/pss-pattern-dp.js`: динамическое программирование по векторам количеств. Разделяет группы на два подмножества, объединяет их вертикальными/горизонтальными сквозными резами с пропилом; переносит координаты деталей, вместо прежней перестройки дерева на фиксированных координатах. Ограниченный набор вариантов сохраняет разные пропорции и оценки числа резов.
- `src/pss-materialize.js`: разворачивает вторичные группы в настоящие экземпляры заказа, резервирует якоря заранее, создаёт первичный spine, обязательный ведущий якорь и полное дерево последующих резов. Все геометрические зазоры обосновываются реальными резами.
- LNS удаляет содержимое хвостов от двух до всех полос, собирает общий пул деталей, распределяет его заново и меняет внутренние деревья; незатронутые хвосты сохраняются. Дополнительно перебирается порядок первичных полос вместе с их настоящими якорями. Пул до 12 разных конфигураций позволяет исследовать варианты, не заменяя ими лучший результат.
- Составные паттерны существуют **только внутри хвоста за якорем**. Их суммарный размер не определяет ширину первичной полосы и не разрешает вращение PRIMARY_REMAINDER.

Все сохранённые параметры бюджета входят в JSON. Исходный PSS 1.2 и его артефакты сохранены для воспроизводимого сравнения. Публичный старый `searchPSS` оставлен прежним; новый API — `searchPSS13`.

## Исследование одного листа и фактический LNS

Перечислено 100 однолистовых конфигураций в исследуемой модели: 64 по H и 36 по V; 1 320 состояний перечисления якорей. ## Ограничения

1. Цель одного листа не достигнута; математического доказательства невозможности нет.
2. Строгие ведущие якоря, HIGH-отделение, LONG_POSITIVE и нулевой дополнительный припуск остаются моделью профиля. Другие технологически обоснованные схемы потребуют отдельного изменения профиля и проверок.
3. DP ограничивает фронт, состояния и переходы. Эвристическое отсечение более крупных габаритов может скрыть полезный точный размер, особенно при зазорах меньше пропила; отдельный retainDominated-режим уменьшает этот риск, но тоже ограничен бюджетом.
4. Ограничены число конфигураций, пул LNS и число групп размеров. При более чем 12 семействах новый DP пропускается и возвращается проверенный базовый результат. Перестройка первичных конфигураций ориентирована на попытку одного листа и двухлистовой вариант с одной дополнительной реальной полосой; на больших заказах LNS работает по существующим полосам, без полного перебора всех многолистовых первичных схем.
5. Два листа не становятся экономичнее по покупке материала только из-за большего остатка; выгода требует последующего использования остатка.
6. Паспортные ограничения реального станка не заданы. Результат условно исполним для указанного абстрактного PSS-профиля, не является сертификацией БАЗИС/станка или программой ЧПУ.

## Правила PSS, реализованные в генераторе и независимом replay

- PRIMARY_PANEL — сырой лист; до первого реза разрешён только указанный профилем предварительный поворот.
- PRIMARY_REMAINDER — единственный основной остаток после каждого первичного реза. Роль наследуется по основной низкой стороне spine; высокая сторона — отделяемая рабочая полоса. Новый blankId не даёт остатку права поворота.
- DETACHED_PRIMARY_STRIP — реально отделённая полоса с реальным ведущим якорем.
- SECONDARY_BLANK — дети рабочей полосы; у каждого независимый turnCount=0 при создании.
- Каждый физический кусок может поворачиваться 0/1 раз в PSS. Разрез завершает существование родителя. В FORMAT_SAW эти ограничения не универсальны: применяются только явно указанные ограничения его профиля.
- endPrimary проверяет список действительно отделённых полос и не меняет роли. Вторичный раскрой и подача как полосы запрещены до завершения первичной серии.
- FINAL_REMAINDER_AS_STRIP — только отдельный явный переход текущего PRIMARY_REMAINDER при доказанном ведущем якоре, точной ширине и реальных резах. Не создаёт новый blankId или новый счётчик.
- В профиле 1.2 anchorAllowance=0: ширина рабочей полосы равна поперечному материальному габариту одного настоящего экземпляра. Произвольного допуска «около» нет. Неподдержанные ненулевые припуски отклоняются; их нельзя выдать за реальные резы.
- Другие детали находятся позади якоря по положительному продольному направлению. После реальной торцовки первым внутренним поперечным резом отделяется полный ведущий якорь; только за ним возможны дополнительные уровни.
- Физические повороты сохраняют материальные координаты/вектор текстуры и не разрешают поворот готовой детали в материале.
- Состояния счётчиков, геометрия, новые идентификаторы, родительские связи, роли и правомерность каждого перехода воспроизводятся заново; сохранённые valid-значки не используются как доказательство.

Положительный регрессионный тест: настоящая деталь 1754 мм впереди последнего остатка позволяет явный переход в полосу.
Отрицательные: старый B006 без якоря; искусственная сумма 874+875+5; неведущий реальный экземпляр; ложный припуск; подмена ролей и первичной карты; повторный поворот; конверсия ещё не распиленного сырого листа ради обхода ограничений.

## Алгоритм PSS

src/pss.js и src/pss-candidates.js — самостоятельный поиск, не вызывающий searchIndustrial/searchStaged и не использующий прежние произвольные составные ширины как первичные полосы.
Рассматриваются обе материальные оси первичного распуска V/H, если они исполнимы при профиле. Для H одноосевая пила V требует предварительного поворота листа, а не смены оси основного остатка после частичного распила.
Каждая новая полоса сразу получает якорь из оставшихся настоящих экземпляров. Все прочие детали могут размещаться только за ним.
Комбинаторный подбор и subset-sum DP рассматривают последовательности **отдельных** реальных полос и кратность экземпляров. Суммарный размер последовательности не становится шириной одной полосы.
Используются сортировки семейств одинаковых деталей, diverse seeded-порядки, локальная переустановка экземпляра и два порядка внутренних разбиений.
DP-перестройка дерева применяется только к хвосту **за неизменным якорем**. Якорный первый рез и первичный spine не перестраиваются в произвольную геометрию.
Цель фиксирована: число листов, крупнейший физически отделимый полезный прямоугольник, число резов, повороты, длина и операции.
Лучшее решение принимается только после независимого физического и PSS replay. Продолжение через options.previous повторно проверяет соответствие нынешней технологии.

## Профиль и обрезка
Одна машинная ось V (x=const); firstCutAxis=V, allowSheetRotation=true, maxSheetTurns=1, allowStripRotation=true, maxTurnsPerBlank=1. Генератор выбирает 0 поворотов исходного листа; тот же план независимо принят строгим профилем maxSheetTurns=0.
Отдельная подача устанавливает локальный машинный (0,0); вращение на 90° меняет локальные размеры, положение полосы керфа и вектор текстуры. При 90° машинный порядок детей может стать обратным материальному.
Материальные координаты и направление текстуры исходной плиты сохраняются. Физический поворот полосы не меняет разрешение на ориентацию детали в материале.
Сначала V-срезы боковых полей и первичный распуск, затем барьер endPrimary. Верх/низ снимаются индивидуально на поданных и повёрнутых полосах. Геометрические поля не подменяются четырьмя разнонаправленными резами по целому листу.

Второй поворот того же blankId запрещён. Пределы уровней, хода и подачи не подтверждены и заданы null; проверяются, если явно указаны. Минимальное удержание условно 0. Модель не проверяет реальные прижимы, толщину и механические коллизии; заданный габаритный конверт подачи проверяется как прямоугольное ограничение, а не как полная 3D-модель станка.
Генератор первой версии строит первичный распуск V; произвольная firstCutAxis H пока не поддержана и отклоняется явно. Ограничения числа стадий/поворотов не вводятся по умолчанию.

## Алгоритм
Сначала выбираются ширины и строится сквозной первичный V-spine, затем детали размещаются внутри независимых полос и их подполос. Произвольное прежнее гильотинное дерево автоматически не принимается.
Кандидаты ширин: размеры деталей, группы одинаковых ширин и ограниченное subset-sum DP для смешанных блоков из двух/трёх физических экземпляров с керфом и реальной кратностью.
Многовариантный поиск использует seeded-перестановки, разрешённые ориентации деталей и оба порядка внутренних гильотинных разбиений.
Каждый четвёртый старт — локальная перестановка двух экземпляров лучшего решения и, иногда, сдвиг границы соседних первичных полос.
Лексикографическая цель: число листов, площадь крупнейшего физически отделимого прямоугольного остатка, максимальный уровень стадии, повороты, количество и длина резов. Все экземпляры обязательны. Цели не переключаются пользователем.
Геометрия проверяется для каждого полного кандидата; потенциальные улучшения проходят независимый staged replay перед сохранением. Продолжение через options.previous повторно проверяет геометрию, пересоздаёт план для профиля и независимо валидирует его.
DP здесь генерирует ширины, не доказывает оптимальность всего раскроя. Оптимальность не заявляется. LNS/полный branch-and-bound не реализованы.

## Алгоритм и проверка
Детерминированный seeded multistart: сортировка по возмущённой площади, три правила выбора свободного прямоугольника, оба порядка гильотинного разбиения, разрешённые повороты.
Лексикографическая цель: число листов, площадь крупнейшего остатка, число резов, длина.
Каждый кандидат проходит независимый валидатор; options.previous позволяет продолжить поиск с проверенным сохранённым решением. Для новых вариантов при продолжении следует менять seed.
Валидатор не импортирует ядро, восстанавливает области из корня и последовательности резов; проверяет точные размеры, керф, нумерацию, экземпляры, повороты, полное покрытие листьями и соответствие карты дереву.
Остатки с нулевой шириной/высотой допустимы при полном расходе припуска на пропил.

## Ограничения
Эвристический поиск, доказательства оптимальности нет. DP, branch-and-bound и LNS не реализованы; исследования этих методов и более качественная оценка полезности всех крупных остатков остаются следующими этапами.
Счётчик states означает число полных стартов, pruned=0: ветвление с отсечениями не заявляется.
Выбор разбиений случаен, перестановки ограничены возмущением площади; решение на одном листе встречается редко.
Геометрия исследовательская, не программа ЧПУ. Отдельные ограничения вращения исходного листа/отделённых полос, захваты, прижимы и допуски станка пока не моделируются.


# Технологическая проверка без вращений — 2026-11-03

Исходная ветка: 735374aa69553ca1fb4d915fe1f68e0a05133a6f. Прочитаны обновлённые AGENTS.md и REQUIREMENTS.md. Изменения ограничены listpro-core/.

## Явный профиль и границы утверждения
Профиль profiles/abstract-fixed-xy-v1.json описывает **абстрактный двухосевой стол**, а не реальное оборудование. allowSheetRotation=false, allowStripRotation=false, allowedCutAxes=[V,H]. V — вертикальная линия x=const, H — горизонтальная y=const в неизменных координатах исходного листа. Доступность обеих осей задана явно как условие профиля.
Заготовки не перемещаются и не перебазируются. Предполагаются независимая фиксация каждой текущей заготовки на месте и доступ инструмента к обеим осям. Минимальные размеры фиксации заданы нулевыми: реальные ограничения неизвестны, поэтому физическую пригодность зажимов это не подтверждает.
Поле maxCutLength ограничивает рабочий ход. Валидатор проверяет вместимость стола, оси, ориентацию, фиксацию и минимальные размеры входной заготовки. Вращения в этой версии не реализованы даже для разрешающего их профиля: такой запрос не подменяется неподтверждённой симуляцией.
Обрезка моделируется четырьмя полными резами; при trim<kerf и trim>0 план отклоняется. При trim=kerf допустим нулевой край, полностью израсходованный на керф.

## Два независимых статуса контрольного заказа
- Геометрия/гильотина: valid=true, 26/26 деталей на одном листе, без поворотов, 38 внутренних резов, 22769 мм.
- Технология: valid=true, **условно для abstract-fixed-xy-v1**, 43 операции (загрузка + 42 реза), 4 обрезки + 38 внутренних резов; 31889 мм с обрезкой. Повороты листа/полос и перемещения: 0.
- V-only без вращения: geometry.valid=true, technology.valid=false, недоступная ось H на шаге 4. При заранее обрезанном листе результат также невозможен для этого заказа: вертикальные резы сохраняют высоту, а всем деталям требуются границы по Y. Это структурная невозможность профиля, не просто неудача поиска; дополнительные листы не помогут.

Пересчёт: seed=1, iterations=100000; распределение 1/2/3 листа = 260/99738/2; states=100000, pruned=0. Время V8 пересчёта с профилем: 26340 мс. Предшествующий геометрический пересчёт тем же seed/бюджетом: 26142 мс, те же результаты. Эти единичные измерения не доказывают преимущество производительности.
Оптимизатор независимо проверяет геометрию каждого старта и технологию каждого претендента, способного улучшить проверенное решение. Технологически отклонённый кандидат не становится лучшим. geometry-only запуск выдаёт technology.valid=null; прежний статус из options.previous не принимается на доверии.
Технологически допустимого решения на одном листе для реального станка не заявляем. Оптимальность не доказана.
