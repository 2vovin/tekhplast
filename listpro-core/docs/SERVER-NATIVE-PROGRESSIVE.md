# Почему программа давала 17 листов вместо проверенных 16

2026-11-07. Пользователь сообщил, что программа разместила новый заказ на 17 листах. В сохранённой исследовательской карте `benchmarks/order-187-target16/` все 187 деталей уже размещены на 16.

## Установленная разница в коде

Исследование использовало native-поиск H/2 с бюджетом **30 с**. Серверный worker ограничивал **каждую** native-попытку пятью секундами, затем переходил к другим стадиям и JS-поиску. Увеличение общего лимита сервера до пяти минут само по себе не увеличивало этот отдельный бюджет. Кроме того, старый установщик сервера сам по себе не устанавливал optional-native-движок. Фактическая версия и наличие движка на VPS не подтверждены: внешний запрос `/healthz` получил HTTP 403; доступа к root-консоли из этой среды нет.

Сохранение карты и кода в GitHub не обновляет работающий VPS и не импортирует карту в его базу опыта. Отдельная карта на 16 листах не доказывала, что прежний серверный конвейер сам найдёт её при коротких попытках. Это расхождение теперь проверяется настоящим HTTP-запросом через сервер.

## Исправление общего поиска

Новый `server/native-search.cjs` не содержит размеров или номеров пользовательских заказов. Если проверенный результат выше нижней границы площади, он выполняет H/V × 2 стадии с бюджетами **5 → 15 → 30 с**, сохраняя каждое улучшение. Если остаётся бюджет, доступны пробы 3/unlimited по 5 с. При достижении нижней границы поиск заканчивается; минимальность резов и поворотов этим не утверждается.

Бюджет конкретного вызова ограничивается оставшимся временем с резервом пяти секунд на replay и checkpoint. Ошибка внешнего движка не удаляет проверенную карту. Технологический валидатор, размеры заказа, текстура и правила удержания не ослаблялись. Оценка минимального числа листов сохраняется и для native-карт.

Диагностика установки доступна через `/healthz`: версия конвейера и наличие native-интерпретатора. Отсутствие движка явно отображается в интерфейсе при оставшемся разрыве до нижней границы; факт успешного выполнения и версия закреплённого пакета проверяются установщиком и каждым native-вызовом.

## Сквозной серверный экзамен с пустой базой

Проверен обычный путь **HTTP API → worker → поиск → сортировка полос → независимый replay → запись опыта → API**, без загрузки эталонной карты. Вход — тот же новый список: 99 строк, 187 экземпляров, 74,519 м²; лист 2750×1830, пропил 5, обрезка 10, все повороты разрешены. Результат:

- Первое проверенное решение — 18 листов, затем 17.
- Попытки H/V по 5 и 15 с не достигли 16.
- Попытка H/2 на 30 с дала **16 листов**; дальнейшие попытки прекращены.
- Полное время API-задачи — примерно **75,7 с** в локальной среде исследования.
- После серверной сортировки: **187 деталей, 16 листов, 446 резов, 149 поворотов**. Длина пропилов 396410 мм. Удерживаемые остатки и исходные листы не поворачиваются; максимум поворотов по цепочке — 3.
- Полный результат независимо проверен, `experienceInfo.saved=true`; повторное воспроизведение из новой базы вернуло 16 листов без нового поиска.

Отдельно проверен **явный импорт** ранее опубликованной карты через тот же `import-verified.cjs`, который используется при обновлении. Worker с бюджетом нового поиска 1 мс воспроизвёл все 187 деталей на 16 листах примерно за **226 мс**, без native-попыток. Это повторное использование проверенной карты, а не новое нахождение за 226 мс.

Данные испытаний: `server/reports/native-progressive/`. Время локальной среды не гарантирует такой же длительности поиска на VPS. Импорт точного проверенного решения позволяет повторять этот заказ без зависимости от длительности нового эвристического поиска.

## Установка на существующий сервер

Из скачанной версии исходников в root-консоли:

```sh
bash listpro-core/server/scripts/update.sh listpro.shortsnews.org \
  listpro-core/benchmarks/order-187-target16/result.json
```

Второй аргумент явно выбирает карту для пополнения базы опыта. Скрипт:

1. Устанавливает PackingSolver 0.1.1301 с проверкой закреплённого SHA256.
2. Обновляет только управляемую установку ListPro и перезапускает её службу; существующие пароль и база сохраняются.
3. Повторно валидирует выбранный JSON и импортирует его от имени `listpro-svc`, сохраняя остальные записи базы.
4. Выводит локальную диагностику `/healthz`.

Конфигурация Nginx и HTTPS-прокси сохраняется. При обновлении установщик больше не предлагает повторную первоначальную настройку HTTPS. Карта не встраивается в код, не раздаётся в примерах интерфейса и не загружается скрыто при обычной установке. Без второго аргумента выполняется только общее обновление.

После обновления нужно загрузить именно `benchmarks/order-187-target16/input.json` или тот же список с теми же параметрами и разрешёнными поворотами. Для изменённого заказа сохранённый план не подставляется без повторного связывания деталей, проверки количества и полного replay.

## Проверки и воспроизведение

Из `listpro-core/`:

```sh
node --test tests/native-search.test.js server/tests/server.test.cjs
LISTPRO_PACKING_PYTHON=/opt/listpro/packing/bin/python node server/scripts/benchmark-native-pipeline.cjs \
  benchmarks/order-187-target16/input.json /tmp/native-api-187
node server/scripts/check-verified-import.cjs benchmarks/order-187-target16/result.json
CHROMIUM_PATH=/usr/bin/chromium node server/scripts/browser-timeout-check.cjs
npm test
npm run benchmark
bash -n server/scripts/update.sh server/scripts/install.sh
```

Проверяются углубление после короткого безуспешного поиска, остановка на нижней границе, сохранение прежней карты при ошибке, ограничение оставшимся временем, отсутствие движка, состав runtime-release и работа после отмены/тайм-аута. Геометрия и PSS проверены; совместимость с конкретным станком по-прежнему требует его параметров.

Результаты: полный набор — **10110/10110**, ошибок нет; целевой серверный набор — 16/16; локальный `npm run benchmark` пройден (архивное внешнее сравнение, включаемое только в CI/явным флагом, не запускалось). Браузерная проверка тайм-аута и ошибок пройдена; проверен граф зависимостей упакованного release и импорт 187 деталей на 16 листах именно в упакованный worker. Bash-синтаксис обоих установочных скриптов проверен. На VPS это обновление из данной среды не устанавливалось.
