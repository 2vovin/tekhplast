# Заказ 229 деталей: исчезновение карты после длительного поиска

Дата: 2026-11-07 (Asia/Irkutsk). Вход: `../../tests/fixtures/order-229.json`, в точности 100 строк / 229 экземпляров из сообщения пользователя. Повороты всех деталей разрешены; лист 2750×1830 мм, пропил 5 мм, обрезка 10 мм. Суммарная площадь деталей 70,58144 м², нижняя граница по полезной площади — 15 листов.

## Воспроизведение

На исходной серверной версии 198a742, пустая отдельная база опыта, iterations=100/seed=42, worker heap 768 MiB: на 298719 мс поиск дошёл до торцовки/смешанных направлений. На 300005 мс внешнее ограничение времени остановило worker. Ни одной карты клиенту не было передано. На реальном VPS пользователь наблюдал исчезновение полосы прогресса без карты; точный журнал его задания недоступен, поэтому локальное воспроизведение подтверждает механизм сбоя, а не заменяет журнал VPS.

Исходный API при тайм-ауте терял все промежуточные решения. Уведомление об ошибке исчезало через 4,5 секунды; постоянная строка статуса находилась внизу рабочей области.

## Исправление

- Быстрый проход iterations=1 перед дорогим поиском с опытом. Далее прежний поиск iterations=100 и прежняя оценка решений.
- Необязательный callback `onBest` вычислительного адаптера передаёт только улучшенные проверенные результаты. Рабочий поток дополнительно сравнивает весь исходный заказ: частичные подзаказы из поиска по базе опыта не могут стать картой полного заказа.
- Перед публикацией карта упорядочивается с технологической проверкой. По целевой функции сохраняется лучшая карта, в том числе если быстрый проход оказался лучше полного.
- Основной процесс удерживает последний checkpoint независимо от worker. По тайм-ауту/ошибке worker возвращает карту с `searchComplete:false` и явным предупреждением. Если карты ещё нет, возвращает ошибку. Отмена пользователем остаётся отменой.
- Ошибки и предупреждения видны постоянно над вкладками, включая не-JSON ответы HTTP-прокси. При промежуточном результате оптимальность не заявляется.
- Checkpoint хранится в памяти процесса, не является дисковой резервной копией. При полном перезапуске службы пропадает. В банк опыта автоматически попадает только нормально завершённый результат.

Время относится к отдельным локальным прогонам, нагрузка среды различалась; оно не доказывает ускорение на VPS. Основное исправление — сохранение результата при ограничении времени. 15 листов не найдено, невозможность не доказана. `result.json` содержит итоговый проверенный вариант; `verification.json` — независимый повторный replay. Геометрия и выбранный PSS-профиль проверены, параметры реального станка неизвестны. Сохраняется прежнее допущение о допустимости конечного пропила с выходом полотна за край отделённой заготовки.

Базовый `npm run benchmark` выполнен до исправления; исторические алгоритмы и технологические правила не изменены.

Данные и отчёт не включаются в runtime release. Изменения требуют обновления службы на VPS; локальные тесты сами по себе не меняют опубликованный сайт.
