# ListPro: серверный расчёт и общая база опыта

Подготовлено для отдельного сайта `listpro.shortsnews.org` на Ubuntu 24.04. Расчёт и библиотека опыта работают на сервере. Браузер получает интерфейс, карты и результаты; исходники оптимизатора не отдаются HTTP-сервером. В репозитории исходники остаются доступными согласно его текущим настройкам доступа.

В этой первой серверной версии один владелец, вход по отдельному паролю HTTP Basic через HTTPS. Регистрация, тарифы, платежи и изоляция нескольких клиентов пока не реализованы. Полный интерфейс показывает все карты, печать и экспорт; ограничений Windows-демо в нём нет. Начальный заказ пустой, частные контрольные заказы не входят в серверный выпуск.

## Изоляция на существующем сервере

- Собственный Node.js **v22.23.4** в `/opt/listpro`. Системный Node.js 18 и его приложения не изменяются.
- Отдельная служба `listpro.service`, пользователь `listpro-svc`, API только на `127.0.0.1:3127`.
- Один вычислительный worker, очередь до 3 ожидающих заказов, время расчёта до 5 минут. Память worker ограничена 768 МБ, служба — 1536 МБ, CPUQuota=150%. На исходном сервере 2 CPU / 4 ГБ RAM это оставляет ресурсы для существующего сайта; нагрузку после запуска нужно наблюдать.
- Своя база `/var/lib/listpro/experience-v1.json`. PostgreSQL и PHP существующего сайта не используются и не перенастраиваются.
- Отдельный конфиг `/etc/nginx/sites-available/listpro-listpro.shortsnews.org.conf`. Конфиги `shortsnews.org`, его wildcard и `cloud.gridhub.ru` не переписываются. Занятое чужое имя/порт/служба останавливают установку.
- Пароль задаётся на сервере скрытым вводом, сохраняются только соль и scrypt-хеш в `/etc/listpro/listpro.env` с правами 600. SSH-пароль root не нужен приложению и не используется.

## Перед установкой

В DNS добавьте **A `listpro` → `81.177.141.65`**, не меняя основную запись shortsnews.org. На сервере нужны curl, tar, xz, sha256sum, python3, nginx, systemctl, ss. Установщик не делает `apt upgrade`, не меняет `/usr/bin/node` и не выполняет глобальные npm-установки.

Из скачанного проверенного исходного архива ветки `listpro-core`:

```
bash listpro-core/server/scripts/install.sh listpro.shortsnews.org
```

Команда проверяет текущий Nginx, скачивает изолированный Node.js с проверкой официального SHA-256, собирает собственный release, создаёт службу и проверяет loopback health. Затем создаётся только новый HTTP-хост для ACME. **До установки HTTPS он возвращает 503, пароль через HTTP не запрашивается.** Параметры доступа вводятся в консоли, не отправляйте их в чат.

Если установка сообщает об ошибке службы, проверьте только её журнал:

```
journalctl -u listpro --no-pager -n 30
```

Не публикуйте env-файл. Установка пока проверена локальными тестами, а не запуском на данном VPS; особенности OpenVZ/systemd могут потребовать корректировки sandbox-параметров службы. Работающий сайт не переносится и не удаляется.

## HTTPS после настройки DNS

Если certbot ещё не установлен:

```
apt-get update
apt-get install -y certbot
```

Затем интерактивно получите сертификат и включите сайт:

```
certbot certonly --webroot -w /var/www/listpro-acme -d listpro.shortsnews.org
bash /opt/listpro/admin/enable-https.sh listpro.shortsnews.org
```

Certbot сам запросит регистрационные данные и согласие с условиями. Скрипт проверяет наличие сертификата, меняет только собственный конфиг, выполняет `nginx -t` и graceful reload, добавляет собственный deploy-hook обновления сертификата. При ошибке синтаксиса прежний конфиг ListPro восстанавливается.

После этого откройте **https://listpro.shortsnews.org**, пользователь **owner**, пароль — заданный вами при установке.

## Хранение и ограничения

Задачи хранятся в памяти процесса: один активный расчёт и до 3 ожидающих. Сохраняются не более 4 последних результатов, срок до 30 минут. После перезапуска незавершённые задачи нужно отправить снова. Уже полученные в браузере карты остаются в текущей вкладке. Данные опыта сохраняются на диске отдельно и переживают перезапуск.

Готовые решения заново проверяются перед записью опыта. Общая библиотека — case-based learning, не нейросеть и не доказательство оптимальности всех заказов. Профиль оборудования исследовательский, реальные параметры станка неизвестны. Материал и толщина описывают заказ; технология стекольного надлома не реализована, минимальный пропил 0,1 мм.

Скрипты тренировки входят в release. Автоматическое накопление происходит после каждого успешного расчёта. Для отдельных экспериментов используйте другой файл базы и ограниченное число задач, например:

```
sudo -u listpro-svc nice -n 10 /opt/listpro/node/bin/node /opt/listpro/current/scripts/self-train-experience.js /var/lib/listpro/practice.json --orders 5
```

Не запускайте несколько обучающих процессов на одном файле. Для резервного копирования базы достаточно копировать experience-v1.json в защищённый каталог администратора; в публичный репозиторий база не включается.

Проверены HTTP-аутентификация, запрет запуска без учётных данных, CSRF, очередь/отмена, настоящий server worker, запись и повторное использование опыта, отсутствие датасетов в release и исходников алгоритма в клиенте. ## Незавершённый поиск и большие заказы (2026-11-07)

Сначала рассчитывается быстрый полный вариант (iterations=1), затем выполняется обычный поиск с базой опыта (iterations=100). Каждый улучшенный полный вариант передаётся в основной процесс после независимой технологической проверки и упорядочивания. Подзаказы из механизма опыта не публикуются как полный результат. Порядок оценки сохраняется: листы, затем выбранная цель и остальные метрики.

При тайм-ауте или ошибке рабочего потока API возвращает лучший сохранённый вариант с `searchComplete:false` и предупреждением. Это не доказательство оптимальности и не завершённый поиск. При отсутствии проверенного варианта возвращается явная ошибка. Предупреждение постоянно видно над рабочими вкладками. Временные варианты находятся в памяти службы (после завершения — до 30 минут), переживают остановку worker, но не перезапуск всей службы. В базу опыта добавляется результат нормально завершённого расчёта; аварийные промежуточные результаты автоматически не добавляются.

Проверки:

```
node --test server/tests/server.test.cjs
CHROMIUM_PATH=/usr/bin/chromium node server/scripts/browser-timeout-check.cjs
```

Регрессия: `server/tests/fixtures/order-229.json`, 100 позиций / 229 деталей, без изменения размеров, с разрешёнными поворотами. Отчёт: `server/reports/order-229/RESULTS.md`. Данные регрессии и отчёты не входят в серверную поставку.

Обновление выполняется повторным запуском `server/scripts/install.sh` из новой версии. Существующий конфиг Nginx, в том числе настроенное доверие к HTTPS-прокси Jino, сохраняется. **Не запускайте `enable-https.sh` повторно на сервере с индивидуальной настройкой прокси**: этот скрипт предназначен для первоначальной настройки прямого HTTPS.

## Профиль завершённых серий (2026-11-07)

Сервер использует `completed-rip-v1`: последняя заготовка после явного END_RIP может требовать дальнейшего раскроя. Во время незавершённой серии удерживаемую часть по-прежнему нельзя поворачивать. Описание: `docs/COMPLETED-RIP.md`.

Новая база: `/var/lib/listpro/experience-completed-v1.json`. Прежняя `/var/lib/listpro/experience-v1.json` остаётся на диске. Проверенную карту нового профиля можно добавить **с объединением, не заменой базы**, от имени пользователя службы:

```
runuser -u listpro-svc -- /opt/listpro/node/bin/node /opt/listpro/current/server/scripts/import-verified.cjs /tmp/verified-result.json /var/lib/listpro/experience-completed-v1.json
```

Импорт повторно воспроизводит план независимым валидатором. Runtime release не содержит пользовательские карты и не загружает их скрыто. Контрольный вариант на 15 листах хранится в `benchmarks/order-229-completed-rip/result.json`; он получен из пользовательского PDF, а не общим поиском с нуля.

## Повторный расчёт и ограничение времени (2026-11-07)

Перед новым поиском сервер воспроизводит полные точно совпадающие схемы из `experience-completed-v1.json`. Частичная схема не запускает поиск в этой быстрой проверке. При достижении нижней границы по площади повторный поиск не запускается (минимальность резов/поворотов при этом не доказана). Если импорт проверенной схемы не выполнялся, само обновление кода не создаёт её в банке.

Каждое улучшение полного заказа проходит независимый replay и сохраняется атомарно до продолжения поиска. Счётчик расчётов увеличивается один раз за задачу; следующие улучшения той же задачи обновляют опыт. Принудительный тайм-аут возвращает последний checkpoint с фактическим флагом `saved`; при ошибке записи карта доступна, но сообщение не обещает сохранения.

Мягкий бюджет поиска — 240 секунд, проверяется между попытками; жёсткий лимит 300 секунд сохранён. Одна длительная попытка может превысить мягкий бюджет. Это ограничение затрат времени, а не доказательство оптимальности. Диагностика тестов: `docs/SERVER-SEARCH-TIMEOUT.md`.
